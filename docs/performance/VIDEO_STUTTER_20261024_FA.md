# رخداد بازگشت ریزلگ تصویر — ۲۰۲۶/۱۰/۲۴

وضعیت: **باز؛ علت و اصلاح قطعی هنوز مشخص نیست.** این سند ادامهٔ PERFORMANCE_RUNBOOK_FA.md و مکمل شواهد همان روز است.

## نشانه و مرز شواهد

پس از انتشار موویی 1.1.0+90، کاربر تصویرِ پرلگ با UI روان گزارش کرد؛ هر دو حالت decoder، حدود دقیقهٔ ۳۰ فیلمِ تصویر ارسالی، و مقایسه با VLC روان‌تر بود. روان‌شدن یک آزمایش تاریخی به معنی حل این رخداد جدید نیست.

نرخ فعال مانیتور با WMI برابر ۱۶۵ هرتز تأیید شد. نابرابری نرخ ویدیو و نمایشگر می‌تواند cadence نامساوی ایجاد کند: مثلاً ۱۶۵/۶۰ = ۲٫۷۵ refresh برای هر فریم. این حساب به‌تنهایی علت لگ شدید را مشخص نمی‌کند؛ VLC نیز روی همان نمایشگر مقایسه شده است. نرخ اعلام‌شده را با نرخ واقعی stream اندازه بگیرید.

در زمان آماده‌سازی ثبت، کاربر برنامه را بست. آخرین watch_last_v1 آن لحظه **Silo، قسمت ۳، 720** بود، نه فیلم تصویر ارسالی. خواندن Range به اندازهٔ ۱۲۸KiB در مسیر مستقیم و پروکسی پاسخ 206 گرفت. header محلی ۸MiB این فایل H.264 High، yuv420p، 1280×536 و 24000/1001 fps بود. bitrate محاسبه‌شده از اندازهٔ چنین فایل ناقصی معتبر نیست. این مشخصات را به فیلم اسکرین‌شات تعمیم ندهید. ffprobe شبکه هنگام خواندن seek/cues timeout شد؛ این timeout شاهد قطع کامل stream نبود.

DLL ریشهٔ نصب `C:/Program Files MBN/MBNMovie/libmpv-2.dll` hash مورد انتظار 04E4D27D…782F4A داشت. وجود فایل درست در پوشه، شاهد loaded module اجرای بعدی نیست؛ Modules فرایند فعال را نیز ثبت کنید. پوشه‌های backup نصب می‌توانند DLL قدیمی داشته باشند و نباید فایل فعال حساب شوند.

## ثبت سطح سیستم

`tools/Capture-WindowsPlaybackFrames.ps1` فرایند MBNMovie، MBNime یا VLC را با PID مشخص می‌گیرد، hash ماژول‌های پخش را ثبت و PresentMon نصب‌شدهٔ رسمی را برای ۵ تا ۶۰ ثانیه اجرا می‌کند. ابزار در مسیر NVIDIA FrameViewSDK موجود بود، اما شروع ETW با **access denied** متوقف شد. در آن تلاش CSV معتبر نمایش سیستم تولید نشد.

نمونهٔ اجرا از PowerShell با دسترسی لازم؛ PID نمونه را عوض کنید:

```powershell
./tools/Capture-WindowsPlaybackFrames.ps1 -PlayerProcessId 12345 -Seconds 30 -OutputDirectory C:/Temp/mbn-presentation-A
```

اسکریپت خودش elevation، عضویت گروه، امنیت ویندوز یا refresh rate را تغییر نمی‌دهد. اگر ابزار خطای دسترسی بدهد، کاربر باید اجرای همان ثبت را از PowerShell دارای دسترسی لازم فراهم کند. [مستند رسمی PresentMon](https://github.com/GameTechDev/PresentMon/blob/main/README.md) حدود شاخص‌ها و دسترسی را توضیح می‌دهد. Presentهای کل برنامه شامل UI هم می‌شود و الزاماً تصویرهای یکتای فیلم نیست.

## ثبت داخلی بدون دسترسی ادمین

در plugin ویندوز هر دو اپ، `frame_trace.h` اضافه شده است. پیش‌فرض خاموش است و فقط وقتی `MBN_VIDEO_FRAME_TRACE_DIR` به پوشه‌ای موجود اشاره کند فعال می‌شود. وقتی خاموش است timestamp هر فریم، log و فایل‌نویسی اجرا نمی‌شود. وقتی روشن است دادهٔ محدود در RAM جمع و هنگام آزادشدن پلیر CSV نوشته می‌شود؛ در هر فریم فایل باز یا flush نمی‌شود.

- `mbn-queue-<pid>-<instance>.csv`: رویداد ۳، فاصلهٔ صف تا شروع Render و زمان CPU مسیر Render.
- `mbn-texture-<pid>-<instance>.csv`: رویداد ۱ Draw، رویداد ۲ Read، انتظار mutex، پایان کپی و serial رندر. serial ثابت در چند Read یعنی خواندن مجدد یک خروجی؛ فاصلهٔ serialها رندرهای میان دو خواندن را نشان می‌دهد.

داده پیکسل، URL پخش، token، متن زیرنویس و نام حساب ندارد. آدرس شیء فقط شناسهٔ محلی instance برای تفکیک فایل است. تا ۱۲۰۰۰۰ رویداد برای هر instance نگه‌داری می‌شود. برای تست طولانی چند ثبت کوتاه بگیرید. خروج اجباری یا crash می‌تواند مانع نوشتن CSV شود؛ برای ذخیره با Back عادی از پلیر خارج شوید.

serial یک Draw است، نه اثبات فریم decode‌شدهٔ یکتا؛ callback می‌تواند برای resize/redraw هم اجرا شود. Read درخواست بافت توسط Flutter را نشان می‌دهد، نه زمان روشن‌شدن تصویر روی پنل. ثبت داخلی باید با مشاهدهٔ کاربر، PresentMon و A/B همبسته شود. `frame-drop-count=0` همچنان کافی نیست.

برای probe جداگانهٔ موویی، پوشه را از قبل بسازید و سپس تنظیم کنید:

```powershell
$env:MBN_VIDEO_FRAME_TRACE_DIR='C:/Temp/mbn-textures'
$env:MBN_QA_CURRENT_STREAM='true'
$env:MBN_QA_START_SECONDS='1800'
$env:MBN_QA_SECONDS='30'
$env:MBN_QA_OUTPUT='C:/Temp/mbn-textures/player.json'
```

probe از preferences موقت استفاده می‌کند، اما CURRENT_STREAM آخرین URL ذخیره‌شدهٔ واقعی را می‌خواند. پیش از اجرا عنوان را با رخداد تطبیق دهید. برای تست قابل اشتراک از MBN_QA_MEDIA و fixture مصنوعی استفاده کنید. subprocess arguments خام یا URL خصوصی را وارد گزارش نکنید. اگر پلیر ساخته نشود، ابزار با MBN_QA_NO_PLAYER و exit code 2 خارج می‌شود.

تحلیل با کتابخانهٔ استاندارد Python:

```powershell
python tools/analyze_frame_trace.py C:/Temp/mbn-textures
```

## اعتبارسنجی ابزار

در `audit/video-trace-validation` اجرای ۱۲ ثانیهٔ H.264 مصنوعی 1080p/30 با core جدید، d3d11va و Flutter محلی 3.47.5 ثبت شد. exit code صفر بود و هر دو CSV و player.json نوشته شدند. این SDK را با CI/اپ نصب‌شدهٔ مبتنی بر Flutter 3.32.8 یکسان فرض نکنید.

| شاخص | ثبت این آزمایش |
|---|---|
| رخداد صف | ۳۷۵ |
| queue wait p50 / p95 / max | 0.005 / 0.028 / 129.588 ms |
| Render p50 / p95 / max | 1.445 / 3.453 / 6.999 ms |
| serialهای متمایز خوانده‌شده | ۳۶۹ |
| serial رندر ردشده میان خواندن‌ها | ۱ |
| فاصلهٔ Read متمایز p50 / p95 / max | 34.254 / 37.808 / 62.085 ms |
| انتظار mutex بیشینه | 2.161 ms |

این پنجره startup و پایان را هم دارد؛ max بدون بررسی محل رخداد به steady state نسبت داده نشود. در stderr اجرای این SDK محلی خطاهای به‌روزرسانی accessibility نیز ثبت شد؛ آن‌ها را پنهان نکنید و همبستگی زمانی را در بازتولید بعدی بررسی کنید. این اعداد فقط صحت مسیر ثبت و baseline مصنوعی‌اند؛ نتیجهٔ فایل ۹٫۴GB یا دقیقهٔ ۳۰ آن نیستند.

## آزمایش بعدی و معیار بستن رخداد

۱. عنوان/قسمت، کیفیت و start time همان رخداد را ثابت کنید؛ نرخ واقعی، codec و hash loaded module ثبت شود.

۲. از همان بازه در اپ نصب‌شده و VLC، ثبت ۳۰ ثانیه‌ای بگیرید. اندازهٔ پنجره، fullscreen و نمایشگر یکسان باشد.

۳. همان بازه در نسخهٔ دارای trace داخلی ثبت شود؛ queue spike، Draw/Read و buffering جدا مقایسه شوند.

۴. اگر نمونهٔ محلی همان بازه روان و شبکه کند بود، Range/سرعت/cache بررسی شود. اگر هر دو در اپ کند و VLC روان بود، render/presentation و driver در اولویت‌اند.

۵. A/B نرخ نمایشگر فقط با اطلاع کاربر و بازگرداندن نرخ اولیه انجام شود. فرضیهٔ 165Hz را پیش از آزمایش به fix تبدیل نکنید.

۶. پس از اصلاح مشخص، همان بازه، ورود/خروج مکرر، software/hardware و هر دو اپ دوباره بررسی شوند. بستن رخداد به تأیید دیداری کاربر همراه با شواهد نیاز دارد.

## ثبت بعدی همان فیلم و تصمیم کاربر

پس از بازکردن دوبارهٔ برنامه، عنوان Spider-Man: Brand New Day با کیفیت 1080 و موقعیت حدود دقیقهٔ ۳۰ تطبیق داده شد. loaded module واقعی libmpv همان hash مورد انتظار بود. Range ابتدایی ۸MiB در ۱٫۶۳۴ ثانیه دریافت شد؛ header فایل H.264 High، 1920×800، yuv420p و نرخ اعلام‌شدهٔ 500/21 بود. این نرخ اعلام‌شده حدود ۲۳٫۸ است و از آن نباید نتیجهٔ cadence واقعی بدون بررسی timestampها گرفت.

probe نخست با Flutter محلی 3.47.5 در flutter_windows.dll با 0xc000041d کرش کرد؛ این اجرای ناقص شاهد زمان‌بندی نیست. probe دوم با Flutter 3.32.8، DLL هم‌هش نصب اصلی و شروع ۱۸۰۰ ثانیه، ثبت ۶۰ ثانیه را تمام کرد. کاربر اجرای دوم را روان توصیف کرد و گفت مسئله در چند دقیقهٔ آغاز پخش است. stderr آن اجرا خالی بود؛ بافر پس از شروع جمع شد و شمارنده‌های drop صفر بودند. صف رندر p95 حدود 0.016ms، Render p95 حدود 15.23ms و فاصلهٔ Read متمایز p95 حدود 57.36ms بود. بیشینهٔ فاصله 2279ms شامل startup است و بدون تفکیک نباید به پخش پایدار نسبت داده شود. این‌ها خواندن بافت‌اند و اندازه‌گیری physical display نیستند.

کاربر سپس صریحاً خواست عیب‌یابی لگ فعلاً کنار گذاشته شود و ده اصلاح پارتی منتشر شوند. رخداد باز می‌ماند. ابزارهای native/QA محلی این مرحله در انتشار اصلاحات پارتی ارسال نمی‌شوند. ثبت بعدی باید چند دقیقهٔ اول را کامل پوشش دهد و از همین فیلم و build همسان استفاده کند.
