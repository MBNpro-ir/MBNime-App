# انتشار و بروزرسانی

نسخه در `pubspec.yaml` و یادداشت فارسی کاربرپسند در `changelogs/<version>.fa.md` نگهداری می‌شود. هر انتشار باید شمارهٔ نسخه و build number بزرگ‌تری داشته باشد. فقط انتشار stable و فایل دارای SHA-256 از مخزن `MBNpro-ir/MBNime-App` نصب می‌شود؛ توکن GitHub هرگز در برنامه قرار نمی‌گیرد.

اکشن روی master، با کش Flutter/Pub/Gradle، مستقیماً بیلد می‌گیرد. مرحلهٔ مجزای pub get، test یا analyze ندارد. خروجی‌ها ابتدا در پیش‌نویس آپلود می‌شوند و سپس انتشار قابل مشاهده می‌شود. یادداشت فارسی انتشار در پیام بعد از نصب نمایش داده می‌شود.

## امضای Android

کلید سرویس نیز از GitHub Secret با نام MBN_API_KEY به زمان بیلد منتقل می‌شود. برای توسعهٔ محلی از فایل ignored به نام `.signing/api-config.json` و `--dart-define-from-file=.signing/api-config.json` استفاده کن. این روش مانع انتشار کلید در سورس است، ولی دادهٔ کلاینتِ داخل اپ را نباید جایگزین احراز هویت امن سرور دانست.

از 1.1.0 به بعد کلید اختصاصی ثابتی لازم است. فایل `.signing/mbnime-release.jks` و گذرواژهٔ DPAPI در `.signing/credentials.xml` خصوصی و ignored هستند. از کلید و گذرواژه نسخهٔ پشتیبان امن و آفلاین بگیر؛ فایل DPAPI تنها با همان حساب Windows قابل بازیابی است. کلید را دوباره تولید نکن. چهار GitHub Secret با پیشوند ANDROID برای CI استفاده می‌شوند؛ وارد کش نمی‌شوند.

برای بیلد محلی از `Build-MBNime-Release.ps1` استفاده کن. برای Flutter مستقیم، متغیرهای `MBN_KEYSTORE_PATH`, `MBN_KEY_ALIAS`, `MBN_KEYSTORE_PASSWORD`, `MBN_KEY_PASSWORD` را فقط در همان پردازش تنظیم کن. بیلد release بدون کلید عمداً خطا می‌دهد.

APKهای قدیمی با debug key ساخته شده‌اند. نسخهٔ 1.0.1 ساخته‌شده در CI کلید موقتی داشته و نمی‌تواند با کلید جدید درجا بروزرسانی شود. نصب اولیهٔ سری جدید باید دستی مدیریت شود؛ پاک‌کردن برنامه باعث از دست رفتن داده‌های محلی می‌شود. از 1.1.0 به بعد کلید ثابت را حفظ کن.

## رفتار آپدیتر

هر راه‌اندازی، آخرین release stable بررسی می‌شود. فایل متناسب با ARM32/ARM64 یا Windows x64 انتخاب و هش و اندازه بررسی می‌شود. فایل ناقص نصب نمی‌شود. دانلود کاملِ نصب‌نشده در راه‌اندازی‌های بعدی دوباره پیشنهاد می‌شود، حتی در قطع اینترنت؛ نسخهٔ جدیدتر جای نسخهٔ آمادهٔ قبلی را می‌گیرد. نصب خودکار بدون تأیید نداریم.

در Windows باید ZIP شامل پوشهٔ MBNime و کل bundle باشد؛ تنها exe کافی نیست. updater.exe کنار exe نصب می‌شود و هنگام اجرا از کپی موقت استفاده می‌کند. پس از آماده‌شدن helper، دانلودها متوقف، برنامه بسته، فایل‌ها جایگزین و برنامه دوباره اجرا می‌شود. فایل‌های قدیمی در `.mbnime-backup-*` کنار برنامه حفظ می‌شوند؛ فایل‌های نامرتبط دست‌نخورده می‌مانند. برای پوشه‌های غیرقابل‌نوشتن ارتقای خودکار متوقف می‌شود، نه اینکه دسترسی مدیر مخفیانه گرفته شود. قطع برق وسط کپی ممکن است بازیابی دستی از backup را لازم کند.

## مخزن انتشار

مخزن عمومی MBNpro-ir/MBNime-App با یک تاریخچهٔ تازه و بدون commitهای خصوصی ساخته شده است. سورس، اکشن و انتشارها در همین مخزن نگهداری می‌شوند. API عمومی برای کاربران نیازی به توکن ندارد. اطلاعات ورود، فایل‌های امضا و خروجی‌های محلی نباید به Git اضافه شوند.
