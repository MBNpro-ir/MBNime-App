# شیوهٔ نوشتن توضیحات انتشار

- عنوان ریلیز فقط نام برنامه و نسخه با پیشوند ⭐ باشد.
- عنوان نسخه را داخل توضیحات تکرار نکنید.
- هر نکته یک بولت کوتاه فارسی با ایموجی مرتبط باشد.
- فقط تغییرات قابل استفاده یا قابل مشاهده برای کاربر نهایی نوشته شوند.
- جزئیات سرور، داشبورد، ابزار ساخت، پایگاه داده، تست و پیاده‌سازی در متن ریلیز نباشند.
- توضیحات بخش بزرگسال در متن عمومی انتشار نباشند.
- برای نسخه‌ای با تغییرات خارج از متن عمومی، حفظ بهبودهای قبلی را بیان کنید؛ قابلیت تازه‌ای نسبت ندهید.
- متن فایل changelogs/<version>.fa.md باید با توضیحات GitHub یکسان باشد.
