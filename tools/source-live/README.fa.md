# دریافت زندهٔ لینک قسمت‌ها

اپ MBNime هنگام باز کردن جزئیات هر عنوان، هم‌زمان اطلاعات عمومی سایت و
`https://mbnime-source-live.mbnpro.workers.dev/v1/titles/<id>` را می‌خواند.
لینک‌های Worker اولویت دارند؛ GitHub دیگر در مسیر دریافت قسمت‌ها نیست.
گردش‌کار قدیمی GitHub برای سازگاری با نسخه‌های نصب‌شدهٔ قبلی حفظ شده است؛
نسخهٔ جدید اپ و وب به فاصلهٔ اجرای آن وابسته نیستند.
فهرست عنوان‌ها، جست‌وجو و دسته‌بندی‌ها همچنان از REST خود سایت خوانده می‌شوند.
MBNMovie بخش بزرگسال ندارد و این اتصال فقط مربوط به MBNime است.

Worker با یک Durable Object نشست سایت را نگه می‌دارد و برای هر درخواست تازه،
صفحهٔ همان عنوان را از سایت می‌خواند. فقط درخواست‌های هم‌زمان یک عنوان ادغام
می‌شوند؛ نتیجهٔ تمام‌شده کش زمانی ندارد و پاسخ `Cache-Control: no-store` دارد.
به‌روزرسانی هنگام باز کردن دوباره یا درخواست مجدد جزئیات انجام می‌شود؛ این
سرویس اعلان push برای صفحه‌ای که از قبل باز مانده است ندارد.

رمز و کوکی سایت در Worker می‌مانند. خروجی فقط شناسه، شماره قسمت، کیفیت و
آدرس HTTPS فایل است. پخش و دانلود مستقیماً از CDN سایت انجام می‌شود.
R2 و کلید S3 برای این مسیر لازم نیستند؛ فایل ویدئو در Cloudflare کپی نمی‌شود.
همهٔ درخواست‌های Worker نیازمند Bearer حساب فعال MBNime و مجوز
`anime_adult_access` هستند. Worker برای هر خواندن، مجوز فعلی را از سرور حساب
بررسی می‌کند؛ نتیجهٔ مثبت کش نمی‌شود. حساب‌های قدیمی و جدید پیش‌فرض مجوز ندارند
و فقط مدیر از داشبورد آن را فعال می‌کند. قطعی سرور بررسی مجوز، دسترسی این بخش
را می‌بندد. در صورت مجوز معتبر و قطعی منبع، جزئیات کامل محلی قابل استفاده‌اند.
این محدودیت بر کاتالوگ عادی و پخش آفلاین عادی اثر ندارد.

## تنظیم و انتشار

از این پوشه اجرا کنید؛ توکن Cloudflare را از محیط امن در
`CLOUDFLARE_API_TOKEN` و شناسه حساب را در `CLOUDFLARE_ACCOUNT_ID` قرار دهید.
توکن به مجوز انتشار Workers نیاز دارد. حساب سایت را با دستور زیر از stdin
به‌صورت JSON شامل `SOURCE_USERNAME` و `SOURCE_PASSWORD` بدهید:

```text
npm ci
npx wrangler secret bulk
npm test
npx wrangler deploy --dry-run
npx wrangler deploy
```

کلیدهای واقعی را در سورس، دستورهای مستندات یا فایل تنظیمات commit نکنید.
برای اجرای محلی می‌توان از `.dev.vars` نادیده‌گرفته‌شده استفاده کرد.
مقدار `ALLOWED_ORIGINS` در `wrangler.jsonc` فقط دامنه‌های وب مجاز را تعیین
می‌کند؛ کلاینت native بدون Origin نیز قابل استفاده است. این محدودیت CORS
جای احراز هویت نیست. مسیرهای دلخواه، متدهای نوشتن و شناسه‌های نامعتبر رد می‌شوند.
محدودیت فعلی هر IP سی درخواست در دقیقه، سه خواندن هم‌زمان سایت و دوازده
درخواست در صف است.

پیش از انتشار، نسخهٔ فعلی و تنظیمات Worker را پشتیبان بگیرید. برای بازگشت
می‌توان از `npx wrangler rollback <version-id>` با شناسهٔ نسخهٔ قبلی استفاده کرد.
پشتیبان‌های محلی در `.wrangler/` نادیده گرفته می‌شوند.

## آزمون

`npm test` اتصال fetch به گیرندهٔ global مخصوص Workers، ورود و محدودیت
redirect، تجزیهٔ قسمت‌ها، خواندن تازه، ادغام درخواست هم‌زمان، سقف صف، محدودیت
درخواست و CORS را بررسی می‌کند. تست‌های Dart در
`test/hentai_details_test.dart` اولویت دادهٔ زنده، دریافت قسمت تازه در درخواست
بعدی، قطعی Worker، ناسازگاری شناسه و حفظ کش کامل را پوشش می‌دهند.

SDK پروژه و CI برابر Flutter 3.32.8 است. اجرای تست با SDK جدیدتر روی
`package_config.json` مربوط به این نسخه می‌تواند خطاهای نامرتبط `dart:ui`
بسازد؛ برای تحلیل، تست و build از SDK هماهنگ استفاده کنید.

برای QA مرورگر، entry point جداگانهٔ `tools/hentai_playback_probe.dart` از
adapter و پلیر واقعی استفاده می‌کند. متغیر `MBN_PROBE_ORIGIN` در تست Playwright
اجازه می‌دهد فقط فایل‌های QA از loopback و با Origin مجاز سرو شوند؛ درخواست
Worker، REST و CDN همچنان زنده‌اند. تست WebKit دسکتاپ جای تست آیفون واقعی نیست.
در تست پخش WebKit با relay، `MBN_QA_LOOPBACK_WORKER=1` فقط هدر CORS پاسخ
زنده را برای Origin محلی آزمون تطبیق می‌دهد؛ بدنهٔ پاسخ همچنان از Worker
خوانده می‌شود. بررسی CORS اصلی با Origin تولید جداگانه انجام می‌شود. این
تطبیق هدر و relay فقط در ابزار QA هستند و در اپ یا Worker منتشر نمی‌شوند.
